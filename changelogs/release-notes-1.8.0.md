本次更新聚焦临时文件与日志的磁盘占用：及时回收失败操作和崩溃留下的缓存，同时保护正在使用的文件、未上传草稿和更新恢复备份。

## ✨ 重点更新

- **临时缓存有明确的回收时机**：远程中转、X11 文件拖出、插件安装与更新解包都补齐正常结束、失败、取消和下次启动时的回收路径，减少用户目录中不易察觉的长期残留。
  - 清扫会避开仍被使用的文件；无法确认用途的旧版无标记插件缓存和恢复备份保守保留，不承诺删除所有历史目录。
  - 变更：`e337b78d` · [PR #722](https://github.com/joesdu/VelaShell/pull/722)
- **日志按天存储，默认保留七天**：统一外部编辑、X Server 与插件日志的日期文件名和过期回收；插件日志入口选择磁盘上实际存在的最新日志，并兼容旧格式。
  - 日志保留设置与诊断包说明同步更新，减少长期使用时的日志积累。
  - 变更：`cc6196d1` · [PR #720](https://github.com/joesdu/VelaShell/pull/720)

## 🖥️ 文件传输与编辑

- **中转缓存更耐异常退出**：Unix 在打开文件后、写入内容前立即移除目录项，数据随最后一个句柄关闭释放；Windows 继续通过句柄删除机制回收。启动及后续中转会清扫一天前、严格匹配命名且未被使用的旧缓存。
  - X11 文件拖出失败、取消或未交接时立即清理；成功交给本机应用的文件保留一天，给接收程序留出读取时间。活跃批次受租约保护。
  - 变更：`e337b78d` · [PR #722](https://github.com/joesdu/VelaShell/pull/722)
- **清理缓存时保护未上传修改**：初次下载失败或内置编辑窗口打开失败会清理半截副本；已交给编辑器的副本通过跨进程租约保护。
  - 关闭自动上传后修改的外部编辑副本仍作为草稿保留，不启动监视或补传；上传仍在进行或收尾超时时，也不把尚未确认写回的内容当作垃圾删除。草稿继续通过消息中心处理。
  - 变更：`e337b78d`、`25c5b1c9`、`38c007c4` · [PR #722](https://github.com/joesdu/VelaShell/pull/722)

## 🔐 安全与隐私

- **自动回收以所有权和恢复能力为边界**：插件包等待确认、安装和已加载开发副本持有租约；新升级备份仅在替换后的插件通过受保护安装回执与完整性校验后回收。清扫跳过链接或重解析点，避免沿链接越过缓存目录。
  - 更新事务记录损坏、回滚未完成或备份用途不明时保留恢复内容；旧版无标记插件缓存无法确认所有权，保守保留。
  - 变更：`e337b78d` · [PR #722](https://github.com/joesdu/VelaShell/pull/722)

## 🐛 修复与稳定性

- **修复插件安装跨文件系统失败**：`.vpx` 解包暂存移至用户插件根下的 `.staging/velashell-vpx`，与最终安装目录处于同一文件系统，避免系统临时目录位于其他挂载点时出现 `Invalid cross-device link`，保留原子目录替换。
  - 变更：`dfd320ce` · [PR #721](https://github.com/joesdu/VelaShell/pull/721)
- **回收失败的更新解包内容，同时保护并发更新**：解包失败立即尝试删除部分内容；启动回收没有事务记录的孤立解包目录。应用目录租约与进程身份标记保护正在解包或等待安装的更新，避免另一个实例误删。
  - 已下载的更新归档和可续传半截文件继续保留供重试；修复更新所需备份不会按普通缓存删除。
  - 变更：`e337b78d` · [PR #722](https://github.com/joesdu/VelaShell/pull/722)

## ⚠️ 升级说明 / 不兼容变更

- 无需要用户额外操作的不兼容变更，不改变插件 SDK 版本。
- 新建插件临时产物带所有权标记；旧版未标记缓存、未上传草稿和用途不明的恢复备份可能继续存在，这是保留数据的边界。
- Linux 继续手动下载安装，Microsoft Store 版仍由商店管理更新。
